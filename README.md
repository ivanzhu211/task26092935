# offer_engine：进程内录用候补时间推进引擎

重演部门季度配额下的录用确认与超时补位。仅依赖 Python 标准库，时间只能前进。

## 快速开始

```python
from datetime import datetime, timezone
from offer_engine import OfferEngine, Event

# 起始 UTC 时刻 + 各部门各季度额度（未配置为零，配置保持不变）
engine = OfferEngine(
    start=datetime(2026, 1, 15, tzinfo=timezone.utc),
    quotas={"eng": {(2026, 1): 2, (2026, 2): 1}},
)

# apply：先自动推进到事件时刻，再处理动作，返回本次新增流转记录
engine.apply(Event(t0, "alice", "enqueue", dept="eng", rank=1))
engine.apply(Event(t1, "alice", "confirm"))

# advance：执行截至 to 的全部自动流转（含补位引发的后续超时）
records = engine.advance(to)

# snapshot：当前候选人状态及配额占用（纯 dict，可直接比较）
snap = engine.snapshot()
```

- 动作仅三种：`enqueue`（需 `dept` 与整数 `rank`，数字小者优先，同排名按编号字典序）、
  `confirm`（仅对待确认有效）、`withdraw`（移除等候者或释放待确认/已确认者名额）。
- 候选人编号全局唯一，仅入队一次；无效动作（如对终态操作、重复入队、
  对已超时者确认）为无操作。恰在期限时刻的确认判为已超时。
- 事件时刻不得早于引擎当前时刻（时间只能前进）。

## 语义要点

- 有可用名额时立即补位；补位者进入待确认，自激活时刻起 48 小时确认窗口；
  新来者不抢占已发出的名额。
- 每次激活消耗其激活时刻所属季度的额度；退出/超时只归还原季度名额；
  旧季度回收的名额不得在当前季度发放；旧季度存活占用不挤占新季度额度。
- 补位发生在逻辑事件时刻：无新输入时，直接 `advance(T)` 与在每个超时点、
  季度边界分段推进再到 T，产生的候选人状态、配额占用与有序流转记录完全一致。

## 内部流转的固定顺序

同一逻辑时刻内：

1. 先处理全部到期超时：按 `(期限, 候选人编号)` 升序逐个超时并释放名额；
2. 再按该时刻所属季度补位：部门按名称字典序，部门内按 `(排名, 候选人编号)`
   升序逐个激活，直到额度用尽或无人等候。

相同时间戳的输入事件按 `apply` 调用顺序处理，每次动作后立即补位。

## 测试

```sh
python3 -m unittest test_offer_engine -v
```

覆盖：基础流转与不变量、季度边界（旧名额超时 + 新季度补位 + 期限确认同时发生、
跨季退出只归还原季度额度）、长区间随机拆分推进与一次性推进的完整记录/最终状态等价、
多轮 48 小时窗口的中间激活与超时保留。
